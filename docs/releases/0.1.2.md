# Etapa 0.1.2 — Restauração do deploy e validação do GitHub Pages

## O que foi feito

- Restaurado `.github/workflows/deploy-pages.yml` na branch `main`.
- Restaurado `.github/workflows/ci.yml` na branch `main`.
- Restaurado `.gitignore` previsto pela estrutura do projeto.
- O workflow de Pages agora executa testes e build antes da publicação.
- O deploy publica exclusivamente o diretório `dist/` gerado pelo Vite.
- O workflow tenta habilitar/configurar o GitHub Pages automaticamente quando permitido pela conta/repositório.
- A CI valida testes e build em pushes para `main` e pull requests.
- Versão do projeto alinhada para `0.1.2` no código e documentação.

## Por que foi feito

A v0.1.1 documentava os workflows de GitHub Actions, porém os arquivos ocultos `.github/...` não chegaram à branch `main`. Sem o workflow, o GitHub Pages podia servir o código-fonte Vite diretamente, fazendo o navegador tentar carregar arquivos TypeScript/TSX em vez do bundle de produção e resultando em uma página vazia.

## Arquivos principais modificados

- `.github/workflows/deploy-pages.yml`
- `.github/workflows/ci.yml`
- `.gitignore`
- `package.json`
- `src/app/App.tsx`
- `README.md`
- `CHANGELOG.md`
- `docs/FILE_TREE.txt`
- `docs/releases/0.1.2.md`

## Como testar

Localmente:

```bash
npm install
npm test
npm run build
npm run preview
```

No GitHub:

1. Fazer push para `main`.
2. Conferir **Actions → Deploy GitHub Pages**.
3. Confirmar que os jobs `Test and build` e `Deploy` terminaram com sucesso.
4. Abrir a URL publicada pelo ambiente `github-pages`.

## Observação sobre dependências

O repositório ainda não possui `package-lock.json`. Por isso os workflows usam `npm install`. Assim que um lockfile for gerado e validado, a instalação deve migrar para `npm ci` para builds reproduzíveis.

## Impacto

Não há migração de IndexedDB nem alteração no modelo de dados. Esta etapa corrige infraestrutura de build/publicação, validação automática e consistência do repositório.
