# Etapa 0.1.0 — Núcleo funcional

## O que foi feito

Foi criada a base executável do Workspace Studio com persistência IndexedDB, biblioteca local de arquivos, planilha editável, histórico, regras de coluna, visualizadores PDF/DOCX/texto, temas e responsividade.

## Por que foi feito assim

O núcleo foi separado por camadas para evitar que React, IndexedDB e parsers de arquivo fiquem acoplados. O arquivo original é preservado e as mudanças acontecem numa cópia lógica interna, o que viabiliza undo/redo e exportação segura.

## Arquivos principais

- `src/app/App.tsx`: fluxo principal da interface.
- `src/database/db.ts`: schema IndexedDB v1.
- `src/database/repositories/`: camada de persistência.
- `src/services/fileImportService.ts`: importação e inspeção.
- `src/services/historyService.ts`: histórico, undo e redo.
- `src/modules/spreadsheet/`: parser, grade e exportação.
- `src/modules/rules/`: regras de coluna e testes.
- `src/modules/viewers/`: PDF, DOCX e texto.
- `src/styles/`: design system e responsividade.

## Como funciona

1. O usuário importa um arquivo.
2. O Blob original é salvo no IndexedDB.
3. Formatos editáveis são transformados em modelo interno.
4. O documento abre em modo leitura.
5. Ao ativar edição, mudanças são registradas no histórico.
6. Regras geram uma lista de mudanças antes da aplicação.
7. A exportação gera uma nova cópia.

## Como testar

```bash
npm install
npm test
npm run build
npm run dev
```

Teste manual recomendado:

1. Importar uma planilha com colunas `Marca`, `Modelo` e `Serial`.
2. Entrar em modo Edição.
3. Abrir Regras.
4. Usar `ABCY-{COLUMN:Marca}-{COLUMN:Modelo}-{SEQ:4}-AABA`.
5. Conferir a prévia.
6. Aplicar.
7. Testar Desfazer e Refazer.
8. Exportar e abrir a cópia em um editor de planilhas.
9. Recarregar a página e conferir se arquivo, regras e aparência permanecem no IndexedDB.

## Validações realizadas nesta entrega

- Verificação sintática dos arquivos TS/TSX: sem diagnóstico de sintaxe.
- Smoke test isolado do motor de serial: aprovado para `0001` e `0002`.
- Varredura de código para uso de `any`: nenhum uso encontrado em `src/`.
- Varredura de `localStorage`/`sessionStorage`: apenas texto informativo na interface; nenhuma chamada de API.

## Limitação do ambiente de geração

A instalação das dependências npm não pôde ser concluída no ambiente de geração por indisponibilidade/timeout de acesso ao registry. Por isso, a validação completa `npm run build` deve ser executada após `npm install` em um ambiente com acesso ao npm.

## Impacto

Esta versão estabelece a arquitetura que as próximas funcionalidades deverão reutilizar, evitando reescrita do núcleo.
